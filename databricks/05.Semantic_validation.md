In a Medallion pipeline, we generally do not throw away the raw incoming data just because it has bad records. Bronze is meant to preserve the raw data so we can reprocess it later. The cleaning and validation happen when building Silver.

Think of it like this:

UPSTREAM SOURCE
      ↓
   BRONZE
(raw data preserved)
      ↓
VALIDATION + CLEANING
      ↓
 ┌───────────────┐
 │               │
VALID           INVALID
 │               │
 ↓               ↓
SILVER       QUARANTINE /
(clean data) REJECTED RECORDS
Your example

Suppose upstream sends:

T1501   quantity=2   unit_price=50     ✅
T1502   quantity=-1  unit_price=70     ❌
T1503   quantity=3   unit_price=-20    ❌

Our semantic rules say:

quantity > 0
unit_price > 0
total_amount >= 0

Then:

valid_df = semantic_df.filter(
    (col("quantity") > 0) &
    (col("unit_price") > 0) &
    (col("total_amount") >= 0)
)

The valid records can continue to Silver.

For invalid records, we have choices:

Quarantine them and tell upstream what failed.
Reject them and request correction/resubmission.
In some business cases, ignore/drop them if the business explicitly allows it.

A good pipeline usually keeps the invalid records somewhere rather than silently throwing them away, because Bronze should preserve the original data and Silver should contain validated/cleaned data.
