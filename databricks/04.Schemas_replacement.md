What does overwriteSchema do?

It tells Delta: replace the existing table schema with the incoming schema while overwriting the data.

So:

inferSchema / explicit schema
          ↓
   Incoming DataFrame
          ↓
    overwriteSchema
          ↓
Replace table's schema + data
Is overwriteSchema evolution or enforcement?

👉 Neither.

It is an overwrite operation that replaces the table schema.

mergeSchema → Schema Evolution

Usually used when you want to keep existing data and evolve the schema.

Example:

Existing table:
product_id | price
P1         | 100

Incoming data:
product_id | price | category
P2         | 200   | Electronics

With mergeSchema:

product_id | price | category
P1         | 100   | NULL
P2         | 200   | Electronics

✅ Existing data stays
✅ New data is added
✅ New column is added to the schema

overwriteSchema → Schema Replacement

Here, you are saying:

Replace the existing data AND use the incoming DataFrame's schema.

Existing:
product_id | price
P1         | 100
P2         | 200

Incoming:
product_id | price | category
P3         | 300   | Electronics

With:

.mode("overwrite") \
.option("overwriteSchema", "true")

Result:

product_id | price | category
P3         | 300   | Electronics

❌ P1 and P2 are replaced
✅ P3 is written
✅ category becomes part of the schema

🧠 Your interview shortcut

mergeSchema

Keep data + evolve schema

overwriteSchema

Replace data + replace schema
===========

Let's use one table product_updates and see actual examples.

1. mergeSchema — add a new column

Existing table:

product_id | price
P001       | 100
P002       | 200

Incoming DataFrame:

product_id | price | category
P003       | 300   | Laptop
P004       | 400   | Phone

Code:

df.write \
    .mode("append") \
    .option("mergeSchema", "true") \
    .format("delta") \
    .saveAsTable("product_updates")

Result:

product_id | price | category
P001       | 100   | NULL
P002       | 200   | NULL
P003       | 300   | Laptop
P004       | 400   | Phone

➡️ Existing data stays.
➡️ New column is added.
➡️ This is schema evolution.

2. mergeSchema — add a nested field

Existing:

customer
  ├── id
  └── name

Incoming:

customer
  ├── id
  ├── name
  └── email

With mergeSchema:

customer
  ├── id
  ├── name
  └── email

➡️ The nested email field is evolved into the schema.

3. Type widening — another evolution example

Suppose:

Existing:
quantity INT

Incoming data uses:

quantity LONG

Certain supported type-widening changes can be handled by Delta when the relevant type-widening capability is enabled.

But this does NOT mean:

INT → STRING

is automatically allowed.

So don't memorize mergeSchema as "it allows every type change."
