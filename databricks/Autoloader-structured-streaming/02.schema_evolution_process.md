# Auto Loader – Schema Evolution

## Objective

Practice how Databricks Auto Loader handles changes in the source JSON schema and unexpected data types.

## Architecture

```text
JSON Files
    ↓
Databricks Auto Loader
    ↓
Delta Bronze Table
    ↓
Schema Evolution
    ↓
Rescued Data
```

## Concepts Practiced

* Auto Loader with Spark Structured Streaming
* Schema inference
* Schema location
* Checkpoint location
* Schema evolution with `mergeSchema`
* Adding a new column to incoming data
* Handling unexpected data types
* `_rescued_data`

## Schema Evolution Example

Initial source schema:

```text
order_id
customer
amount
```

A new file introduced:

```text
channel
```

Auto Loader evolved the Delta table to include the new column. Existing records received `NULL` for the new column.

## Unexpected Data Type

The source contained:

```json
{
  "order_id": 4,
  "customer": "Sanjay",
  "amount": "NOT_A_NUMBER",
  "channel": "Store"
}
```

Since `amount` was expected to be numeric, Auto Loader stored:

```text
amount = NULL
```

and preserved the unexpected source value in `_rescued_data`.

## Result

The record was not lost. The valid records were loaded normally, while the unexpected value was captured for further data-quality investigation.

## Key Learning

Auto Loader can handle changing source schemas and unexpected source data while maintaining the streaming ingestion pipeline.
