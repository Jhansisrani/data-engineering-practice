

 create the Stream with APPEND_ONLY = TRUE and then don't use the WHERE METADATA$ACTION = 'INSERT' condition, the Stream itself contains only the INSERT changes.

So in our example:

CREATE OR REPLACE STREAM staging_append_stream
ON TABLE staging_table
APPEND_ONLY = TRUE;

Suppose i do:

INSERT INTO staging_table VALUES (7, 'Alteryx', 0);

UPDATE staging_table
SET fee = 10
WHERE id = 7;

Then:

SELECT *
FROM staging_append_stream;

The Stream will contain the INSERT event, roughly:

ID	NAME	FEE	METADATA$ACTION
7	Alteryx	0	INSERT

The UPDATE to fee = 10 is not captured by the append-only Stream.

Therefore, even if i do:

INSERT INTO prod_table (id, name, fee)
SELECT id, name, fee
FROM staging_append_stream;

the production table receives:

7 | Alteryx | 0

not

7 | Alteryx | 10
Compare with a normal Stream

If i had:

CREATE OR REPLACE STREAM staging_stream
ON TABLE staging_table;

then an update can appear as CDC changes (a DELETE + INSERT pair), and i'd normally use a MERGE to apply the latest state correctly.

So:

APPEND_ONLY = TRUE
       ↓
Only INSERT changes captured
       ↓
SELECT from Stream
       ↓
INSERT into prod
       ↓
New records only

That's exactly what current exercise is demonstrating.
